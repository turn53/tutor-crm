## Данные и секреты

`server-data/crm.sqlite3` содержит записи, историю изменений и долговечные очереди.
`server-data/google.local.json`, `server-data/zoom.local.json` и `.env` нужны для
восстановления интеграций и прежнего входа. Они не входят в Git.
`server-data/videos` — рабочие файлы видео, `server-data/backups` — ежедневные
копии SQLite. Сами готовые записи доступны по сохранённым ссылкам на Zoom/YouTube.
`models` содержит обе перенесённые модели; рабочая — `qwen35-4b-q4.gguf`.
Тома Docker `tutor-crm_caddy_data` и `tutor-crm_caddy_config` содержат состояние Caddy.

GitHub хранит код, тесты, инструкции и контейнер приложения. GitHub не заменяет
резервную копию базы, ключей интеграций и томов HTTPS. Не добавлять такие файлы в Git.

## Копии для восстановления

На новом сервере `/root/crm-migration/final-data.tar.gz` и `final-manifest.json`
содержат окончательную копию данных и её контрольные суммы.
`snapshot.tar.gz` и `manifest.json` — предварительная копия приложения,
настроек, старых резервных копий и томов Caddy (без моделей).
Те же исходные архивы сохранены на компьютере владельца в
`tutor-crm/.runtime/migration-20260927`. Доступ к ним должен оставаться закрытым.

Точный контейнер старого рабочего приложения сохранён в приватном релизе
`production-2026-09-27`. SHA-256 `crm-image.tar`:
`8ca723dc5794f6f95f2ed45de8f96eeeecac2bbd7175cbaa9afefb88cabfb1d3`.
Активная модель: `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`.
Архивная модель: `3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597`.

Для восстановления сначала остановить CRM и исключить одновременную работу двух
планировщиков. Восстановить базу через SQLite backup API либо из проверенного
архива остановленной CRM; проверить целостность, таблицы и файлы. Дать UID 10001
доступ к `server-data`, восстановить `.env`, настройки интеграций, модели и тома
Caddy. Проверить локально, затем запустить `docker compose up -d --no-build` с
предварительно загруженным проверенным образом. Для свежей сборки использовать
`docker compose build crm`, проверив результат до подключения рабочих данных.

## Старый сервер и откат

Beget `45.130.42.186` сохранён. CRM на нём остановлена, фронтенд показывает
техническую паузу для клиентов со старым DNS-кэшем. Исходный Caddyfile находится в
`/root/crm-migration/final-cutover/Caddyfile.original`.
Не запускать старую CRM одновременно с новой.
После появления изменений на OneDash нельзя откатываться простым включением
старой базы: сначала остановить новый экземпляр, сделать и проверить свежую копию,
перенести её обратно, затем восстановить Caddy и DNS. Старые данные нельзя
накладывать поверх новых без сверки.

Ежедневный бэкап на том же диске защищает от ошибочных изменений, но не от потери
всего VPS. Отдельную копию следует сохранять вне этого сервера.
